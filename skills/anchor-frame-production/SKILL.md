# 锚定图制作 SOP

## 确定任务
先读当前项目、对象、提示词和真实参考数组。只改提示词时只写草稿，不生成、不弹生成确认。单镜任务不强制扩展整组；不引入首尾帧流程。

## 参考分工
给每张真实参考标明唯一主职责：身份服装、道具结构、环境空间、构图或色彩。按提交数组核对 @图片N，不猜编号、不为套模板重排既有参考。左右须明确是人物自身、车辆自身还是画面左右；车型、年份、驾驶位、台词时长均来自本项目，不使用案例默认值。
按地点、时间、天气、主光方向分组，室内外分别判断光线。已有获认可底图则继承构图做必要替换；没有合格底图才直接生成锚定候选。

## 提示词
按需组织六项：主体与环境；审美；镜头机位；物理光照与色彩；材质；空间、结构与禁止变化。明确本次改什么、保留什么。色卡统一引用一次。生成前给出参考顺序与角色说明，生成后核对工具 reference_order 回执。

## 局部核验
使用实际图片证据，原生识图优先。细字、驾驶位、空间关系先用 image_inspect 裁切；裁切不会创造细节，看不清就记为未知。不要被“是不是已经对了”诱导，只陈述可见证据、反证和遮挡，缺陷给出区域与主观置信理由。
要求“其他地方不变”时用 image_inspect 的 compare_to 和 region 对同尺寸图做像素差分。阈值0才是严格像素相同；压缩和色彩变化也产生差异，像素指标不等于语义正确。不得仅凭印象宣布完全没变。

## 版本与连续性
沿用现有候选、版本、采纳入口，不自动覆盖或删除旧图。每个候选记录路径/版本、参考顺序、修改目标、核验结果（通过/失败/未知）、证据、否决理由、允许偏差、空间前提与跨镜连续性。记录可写在当前项目文案中，以“锚定图记录”小节保存；无项目则在当前对话明确输出该记录，用户需要持久文件时再保存。只有用户认可的图才能称为定版，不能把生成成功当定版。
同环境先核验锚点再并行变体；独立环境可并行。延续人物服装、道具状态、房间拓扑、门窗与光源。

## 工具使用与异常
- 先查内置能力/tool_search，再查脚本渠道，不用局部渠道清单推断全局支持情况。
- 批量任务逐项读 receipt：completed、submitted、unknown、not_submitted 分开处理。unknown 不重提、不换渠道，不用目录是否有文件判定扣费结果；task_status 的远端 ID 才是已收到提交凭据，仍不等于生成成功。
- 长文档修改先通过 copywriting_get_state 的 block_ids 或 query 获取目标完整块及新 hash，再 patch；不凭截断预览判断写入失败。
- 同轮重复 skill_invoke 默认摘要；上下文压缩后需要全文时 force_full。

需要记录时读取 `references/version-record.md`，沿用字段写入已有项目文案；不要只在压缩前的临时上下文里记住。

## 汽车驾驶安全带（强制）

汽车驾驶画面强制规则：凡画面涉及人物驾驶汽车，最终图片或视频提示词必须明确写出“驾驶者全程正确系好安全带，肩带斜跨胸前、腰带贴合髋部并扣紧”；不得仅写在分析或负面提示中。换机位、局部修改、风格改写和连续镜头均须保留此约束，不得出现安全带消失、解开、穿模或置于背后。近景可见部位必须正确呈现；遮挡时保持佩戴事实，不为展示安全带擅自改变构图。纯车辆空镜不新增人物。
核验驾驶人物时检查安全带；明确缺失或佩戴错误的候选不得判为合格，遮挡看不清须标记未确认。
