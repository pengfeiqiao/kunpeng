# Blender 建模与工程编辑

优先沿用用户给定的工程、参考和规格。区分完整建模与白模预演，不能因为提到 Blender 就简化成方块白模。信息足够时直接工作，只询问会改变结果的重要缺失信息。

## 选择执行路径

先检查实际可用的 Blender MCP 工具；没有时探测本机 Blender，通过 bash 运行 bpy 脚本。路径与 shell 以运行环境为准。未安装时说明缺少依赖，不能声称工具已经连接。不要要求用户重新填写语言模型 Key 来连接本地 Blender。

网页资料优先用浏览器 snapshot 引用。Blender 场景数据优先用 bpy/MCP，只有需要界面交互时才使用已接入的桌面工具。不能把网页浏览器工具当成整个桌面控制器。

## 场景与修改

1. 读取 Blender 版本、当前文件、场景、对象和集合、单位、相机、渲染器及资源路径。已有文件先另存工作副本；不得用 factory-startup 或清场脚本修改原工程。
2. 明确尺寸、轴向、命名和目标集合。通过稳定对象名称/自定义标识查找并更新，避免每次重试生成重复对象。操作符依赖模式与活动对象时先校验上下文；纯数据操作优先使用 bpy.data/bmesh。
3. 按可验证的小批次修改：几何和比例→材质→灯光相机。每批读取真实场景数据检查对象数量、尺寸、变换、可见性与修改器；代码没有报错不代表造型正确。
4. 使用低成本预览检查轮廓、比例、构图、穿插和材质，图片交给当前模型原生视觉。根据需求选择视角，不机械生成固定数量视图。修正后再做最终渲染。

## 运行与交付

- 同一场景的修改串行执行。超时或断连后先检查进程、日志及输出，不能直接重新运行创建/渲染脚本。长渲染用当前可用的任务机制；若仅支持 bash，设定合理 timeout，不能虚构 jobId 或恢复能力。
- 保存 `.blend` 到明确的工作目录，处理外部贴图依赖。新进程重新打开保存文件，读取关键对象、相机与资源确认可编辑；只有完成该检查才称工程已验证。
- 提供工程及用户要求的导出/预览，并简要说明实际完成的验证。不能只交截图却声称已经完成可编辑模型。
- 付费外部素材/生成遵循现有授权机制；本地失败不能触发付费重复提交。保持用户原有工作流，不新增按钮或强制首尾帧步骤。
