# 运行时优化与附件串会话修复

## 附件归属

根因是 MessageInput 挂载时注册的原生拖拽监听捕获了旧的 fileDraftKey。切换会话不重挂载组件，回调仍调用旧会话的草稿 setter。

现在原生 drop 回调在事件发生时通过 store 原子读取当前会话并追加附件；保留去重和各会话独立草稿。文件/文件夹选择框沿用打开时捕获的会话目标。晚到的已卸载监听事件直接忽略。

回归既覆盖 store 动作，也加载真实 MessageInput 的原生监听：注册监听→切换会话→触发 drop，确认新会话收到附件、旧会话没有被写入。

## 共享运行时

- 会话写盘最多尝试三次，失败向调用方返回错误，保留最新未写快照；新保存或窗口重新聚焦时恢复。部分 UI/agent 历史合并保留，删除会话会清除待重试状态。沿用原子替换和串行写入，没有迁移历史格式。
- 当前对话保存失败时在现有标题栏显示简短状态，不增加按钮。未落盘数据仍依赖当前进程内存/已有本地缓存，不能保证强制退出后保留全部最新内容。
- 摘要失败状态归属于 coordinator，按模型/供应商隔离。连续三次失败后暂停请求摘要服务一分钟，期间本地摘要仍可执行；成功后复位。取消立即结束等待，不计入故障，不将迟到结果作为成功返回。
- 命令 stdout/stderr 分块写临时文件，内存不再累计完整输出。每个流保存上限 16MiB，超过后继续排空管道但丢弃超额内容并明确标记；已完成输出缓存最多 24 条、128MiB，保留期一小时。UTF-8 跨块解码与按字符分页保持正确。输出缓存淘汰时释放文件。
- 大型工具集（超过 40 项）提供核心工具及加载目录，按需加载完整 schema；加载状态按 coordinator 隔离，禁用工具不可借此重新启用。小型工具集和 DSH 的工具桥保持原有暴露方式，未直接启用中转站未验证的原生 deferred-tools 协议。
- 请求消息预算扣除本轮实际工具定义估算、输出预算和协议余量，保留原有保守比例；稳定 schema 的估算结果缓存复用。
