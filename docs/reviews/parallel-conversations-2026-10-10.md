# 对话并行、切换与软件执行审查（2026-10-10）

## 根因与修复

原实现按 agentId 缓存执行器，同一个 main 助手的多个会话实际共用历史、取消控制和部分临时工具状态。仅放开导航限制会出现串话。现在执行器、DSH bridge、恢复 Promise、运行编号、取消代次、工具记录均按 sessionId 隔离；每个会话仍只允许一个主运行，运行中的补充消息交给其自身队列。

展示层保留现有字段兼容画布/文案/工坊抽屉，增加按会话保存的视图快照。切换原子保存/恢复消息、输出、阶段、草稿、错误、上下文统计。后台更新只能写自己的快照；后台完成标记未读，不能覆盖前台输出。附件继续使用既有按会话持久化草稿。

修复全局“五秒相同内容”去重误伤另一会话；去重现在包含 sessionId。停止只找当前会话，取消的旧代次和完成后的迟到回调不能再写历史或覆盖新运行。DSH 返回后也先检查归属/取消再入库。保存 UI 历史、Agent 历史和窗口关闭存档使用同一会话键，不能把当前可见消息写进后台文件。

工具注册表每会话克隆，待办/后台任务/定时任务绑定来源会话，工坊编辑的运行号显式传入。每轮冻结来源视图、技能检索范围、项目提示上下文与生成确认偏好。后台 switch_view 更新该会话工具范围，不抢前台页面。确认框沿用现有设计，新增来源对话文字；确认仍按 runId 分组和撤销。运行中的会话禁止直接删除。

## 切换与资源开销

- 导航不再恢复执行器，也不等待模型总结/压缩。模型历史在发送时按需恢复；restoreMessages 只做本地处理，网络压缩留给运行的 preflight。
- 回到已打开会话优先读取内存快照；同会话切换不再强制全量历史写盘。
- 前台流式刷新约 80ms，后台约 400ms；后台 token 更新保持前台消息和侧栏运行集合的对象引用稳定。
- 历史消息与已完成执行记录使用 React.memo；列表直接携带消息索引，去掉逐条 findIndex 全量扫描。
- 执行器缓存超过 12 个时，先保存后回收空闲项；正在运行、正在恢复、当前可见以及保存中重新启动的会话不回收。全部为运行态时允许超过此数，不中断任务。
- 共享电脑/浏览器/Blender 工具以 runId 持有控制权，避免另一对话在“截图—操作”间改动外部状态。同一拥有者内部也串行；独立模型、生图、视频任务不被这把锁串行化。取消排队不执行；已进入工具调用的操作结算前不交接控制权。

- [DeepSeek Harness agent-loop](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/core/agent-loop/README.md)：会话绑定及工具并发边界。采用独立会话并发、共享可变外部资源互斥。
- [DeepSeek 会话作用域设计](https://github.com/deepseek-ai/deepseek-harness/blob/master/.agents/notes/implemented/architecture/2026-07-25-web-client-session-scope-and-provide-channel.md)：作用域由宿主管理，不能从当前界面反推后台任务归属。

## 验证范围

新增真实 useAgent 函数体的受控执行测试，覆盖同一助手并行两会话、相同请求不误拦、独立输出/入库、补充消息、停止、迟到结果、重复完成、停止后立即重发、来源确认和缓存回收；分别进入 Kimi、GPT 和 DSH 分支，模型/IPC 使用可控替身以确定性制造竞态。

真实 store 测试验证消息、附件草稿、文本草稿、流式状态隔离，以及 1000 次后台 token 更新不更换前台消息/侧栏集合引用。真实 ToolRegistry 测试验证共享软件排队时独立生图仍可执行；已有工坊目标版本、付费幂等、确认、持久化和 ACP 测试继续回归。

这不是网络模型并发压测，也没有将桌面软件实际帧率或用户机器上的改善幅度当作已测数据。共享项目目标变更仍保留失效保护：切换到另一个工坊项目后，旧任务不会越过校验写错项目。软件租约覆盖规范工具入口，不把任意 shell 命令判定为可安全并行的 GUI 操作。

## 第二轮专项复查

上一轮正常运行路径的测试通过，不等于启动和退出间隙都正确。本轮主动制造延迟，确认并修复：

1. 启动准备期间连续发送会被 busy 分支丢弃。改为每会话的准备队列，执行器接管后按原会话交付补充；不同会话不互相等待。
2. 停止发生在历史恢复期间，旧恢复可能晚到覆盖新执行器。恢复增加 Promise 身份校验，停止撤销准备代次；旧等待者不能启动新任务或删除新的恢复状态。
3. 五秒同文去重会误吞停止后的立即重试，且没有比较附件。移除时间窗去重，以运行归属和准备队列防止同时启动。
4. DSH 回答已完成但 ACP 仍在清理时，补充可能被接受后直接清空。Bridge 显式关闭补充入口；宿主等待该轮清理完成，再把请求作为下一轮执行。
5. 小对话框文字草稿原先是组件局部状态。改为会话草稿，和附件一样随会话切换，避免串到另一个对话。
6. 软件租约结束时，未带取消信号的排队调用仍可能继续执行。结束运行显式拒绝该运行的排队项，已进入的调用结算后再交接控制权。
7. 准备中的请求尚未设置发送锁，可能被空闲缓存回收。回收同时检查准备队列；工作目录切换/清空也不改动准备中的执行器。
8. A 等待恢复时，B 改模型会影响 A 的路由选择。设置快照在提交时捕获。
9. 首次发送创建会话，写盘尚未完成就切走，会导致初始化返回 null 并丢消息。提前记录同步发布的会话 ID，后续发送保持归属。删除会话也清除残留流式索引。
