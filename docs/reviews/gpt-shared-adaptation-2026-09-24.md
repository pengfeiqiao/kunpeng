# GPT / MCP / Blender 共享适配实施记录

本轮依据二次调研和用户授权，将通用基础设施统一修复，模型差异保留在现有 Provider。没有新增界面按钮。

## 已实现

- MCP stdio 按连接隔离进程，后台分发器按 JSON-RPC 请求 ID 匹配响应，通知不再占用请求响应；初始化通知立即完成，不再等待一个不存在的回复。
- 支持同一服务内多个在途请求与多个服务并存。关闭服务只处理对应进程树；macOS/Linux 使用独立进程组，Windows 使用不弹控制台的 taskkill /T /F。
- MCP 调用贯穿 AbortSignal；取消向服务发送通知并停止等待。取消/超时不代表远端操作回滚，返回结果明确要求先查状态，不自动重放。
- HTTP 不再把 -32600 当会话过期并重发工具；JSON/SSE 响应必须匹配请求 ID，忽略进度和其他请求的响应。
- MCP 初始化、重载、微信与飞书入口取消 GLM Key 依赖。服务只能通过 credentialId 显式引用凭证注册表，本地无认证服务不注入其他模型的 Key。
- 分页发现工具；失败时清理连接。MCP structuredContent-only 场景数据能够进入模型上下文。
- 浏览器截图在 nativeVision 路径直接回传图片，GPT、DeepSeek、Kimi 共用；非原生视觉路径保留文件识图方式。浏览器交互仍用已有 DOM 引用。
- GPT Responses 重放中的消息/函数调用不再与已有消息字段重复计入上下文预算；加密推理状态仍计入。
- 新增后台 Blender 建模参考技能，区分通用建模与白模运镜，要求真实场景检查、增量更新、预览和保存后重开验证；不新增可点击工具。
- 原白模渲染脚本在渲染前和成功后保存 `.blend`，结果包含工程路径。

## 验证

- 全量 test:harness：903 项通过（后续新增的结构化结果、取消及技能加载测试另行通过）。
- test:context：15 项通过；test:dsh-runtime：5 项通过。
- 最终 MCP/浏览器/上下文定向测试：20 项通过；产品 SkillLoader 测试：8 项通过。
- Rust 使用真实 Python stdio 模拟进程，验证两服务并存、乱序响应、进度通知及关闭隔离。
- 生产前端构建通过；最终 TypeScript 类型检查通过，Rust 多服务集成测试通过。构建仍有原有的包体积和 Rust 宏警告。
- Blender 4.5.3 LTS 实际执行白模脚本，Workbench 渲染两帧。新进程重新打开 `.blend`，验证 7 个场景对象、2×2×2 测试立方体、相机及帧范围；预览已人工视觉检查。
- 通用 Codex skill 校验器不接受鲲鹏扩展的 category/displayName/triggers/visibility 字段，因此以产品实际 SkillLoader 加载验证为准，保留鲲鹏现有技能格式。

## 边界

DSH runtime、DeepSeek/Kimi Provider 和调用循环未替换；兼容性证据包括既有 DSH 桥、媒体回传和生命周期回归。本轮没有再次进行付费模型端到端调用，也没有进行 Windows 实机验证。

外部 MCP 服务列表仍保持用户现有配置，本轮没有擅自安装桌面控制或 Blender MCP 服务。浏览器原生截图及本机 bpy 路径已增强；不能把这些工作描述为已经接通完整操作系统桌面控制。

通用渲染任务队列、桌面截图坐标/窗口版本合同、有限只读并行及按尺寸计算图片预算仍属于后续工作，未混入本轮。当前优先解决错误路由、重复执行、服务互相覆盖和截图多走一次识图的问题。
