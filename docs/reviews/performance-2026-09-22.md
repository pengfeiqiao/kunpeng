# 鲲鹏卡顿排查与修复（2026-09-22）

## 结论与证据范围

报告中的历史快照负载问题成立：原保存路径在前端主线程序列化当前项目和全部历史，随后整个文件经 IPC 写盘。40 条上限只能限制数量，不能限制总字节数。报告将应用称为 Electron 不准确（实际为 Tauri），累计 page-in 也不能单独证明当前内存压力。“已是最新版”不能排除版本回退。

报告的 35.8MB 项目并未提供；本机只读抽查的最大 workshop.json 约 1.95MB，与用户现场不同。因此本次结果是代码链路审计、自动回归及合成负载验证，不是用户现场帧率或卡顿时长测量。没有删除用户历史、素材、下载目录或工作区。

## 已修复

1. **历史重复序列化和写盘**：历史主体拆到项目内 `history/<hash>.json`，主文件保存轻量索引。首次保存旧项目时逐条迁移；后续只写新增/变化的历史和当前项目。按项目串行提交，先持久化历史再提交索引。缺失或损坏的历史会中止加载，不会被当作空历史覆盖。历史回退接口仍得到完整记录。
2. **输入同步存储**：工坊助手输入草稿由每次按键同步 JSON/localStorage 改为 250ms 合并；内存和 UI 仍立即更新，提交、状态变化、页面退出立即刷新。100 次连续输入回归只产生一次延后持久化。
3. **生成前复制整个项目**：配音/声音生产只冻结必要的角色、镜头和确认策略，不再复制全部项目及几十 MB 历史。现有付费确认、作用域和修订校验保留。
4. **选择对象触发全索引重建**：保存归一化仅在内容引用变化时执行；仅视图或历史变化时复用已有对象/媒体索引，避免无意义的 store 发布。任何其他顶层字段变化都保守重新校验，不只列举部分内容字段。
5. **文件替换**：项目文件写临时文件后重命名；写入/替换失败保留原文件并让严格保存报告失败。
6. **导入兼容**：原有打包递归包含项目子目录；导入补充历史文件的项目 ID 和素材路径重映射，避免历史拆分后跨机器回退引用旧路径。

## 验证

- 全量 test:harness：859 项通过；随后新增原子写盘故障回归单独通过。
- 历史/归一化/原子写盘定向测试覆盖：旧格式迁移、完整读回、分支、丢失文件、路径越界、失败保留旧索引、并发保存顺序、同对象内容修改、纯视图保存与内容变更重新校验。
- 40 条、每条约 900KB 的合成历史：原内联序列化约 36MB；新主索引约 6.5KB（测试当前项目为空，不代表实际项目主文件会缩至这个大小）。后续编辑只写一次主文件，历史仍保留 40 条。
- npm run build 通过；Rust cargo check 通过。构建仍有既有的大 chunk 和 Browserslist 数据陈旧提示。
- 画布自动保存已有延后/合并调度，run-step 持久化已有合并机制；本次未以重复节流替换它们。未发现报告所称的无上限快照数组（现有上限 40）。

## 实际限制

- 当前打开项目仍会加载历史到内存；本次重点消除日常操作重复序列化/复制/写盘，未实现历史懒加载。首次迁移和打开超大项目仍有开销。
- 保留历史文件，不在本次迁移中主动删除孤立文件。后续磁盘回收需单独实现引用核验与故障恢复。
- 新格式需要支持历史索引的客户端；不能把迁移后的 workshop.json 单独复制给旧客户端。项目导出应包含整个项目目录。
- 源码和构建已验证，但没有对用户现场超大项目进行安装后连续使用测试，也没有更改已安装应用。
