## 文档 Props

```tsx
const documents = useWorkspaceDocuments(project.id);
// hooks固定调用，显示由父壳surface决定。
{documents && <WorkspaceDocuments {...documents} />}
```

- 组件：`src/components/workspace/WorkspaceDocuments.tsx`，default export。
- 生产端口：`src/lib/workspace/documentsStoreAdapter.ts` 的 `createWorkshopDocumentsPort`。创建端口不读盘、不扫描；读取发生在文档选择后。`skills` 使用现有 `useSkillStore`，不是另建市场。
- 生产hook：`src/lib/workspace/useWorkspaceDocuments.ts` 的 `useWorkspaceDocuments(projectId)` 返回 `WorkspaceDocumentsProps | null`。已封装port、sources、skills、revision；身份未对齐返回null；只有现有Skill目录尚未加载时调用原loadAllSkills。父无需重复实现adapter或订阅。
- `revision` 是原文刷新信号；收到变化只更新干净稿，有未保存稿时保留并显示冲突。模块默认 `workspaceDocumentDrafts` 在视图卸载后仍保留当前进程的草稿，按 projectId + 文档身份隔离。可传独立 `WorkspaceDocumentDrafts` 实例供测试；不要每次 render 新建。
- 原剧本只从 `project.sources` 登记的同项目 `sources/<name>` 读取；不使用 synopsis、episodes、projectIntake 或 AI 摘要假冒原文。Markdown/TXT 直接读写原文件。DOCX/PDF/XLSX 提供打开原件；链接只显示来源，不自动联网。
- 规格与创作规则都是 `projectSpec` 的可编辑投影，编辑态为字段表单，不另存 JSON/Markdown。保存调用与原 SpecEditor 相同的 `workshopStore.updateProjectSpec`，随后 `commitNow({requireSuccess:true})`。`bibles`、镜头事实、对白及 style 等其他数据不在此模块编辑范围。
- Skill 正文读写已有 `SKILL.md`；内置 Skill 只读可导出。Markdown 导入使用唯一目录与 `skill.json` 稳定 ID，以便现有 `loadSkills`/Agent 共用加载器识别；正文只存在 `SKILL.md`，manifest 不存平行正文。
- 启停调用原 `skillPreferences`，不新增存储 key。原结构只有一个 Skill 对应一条 global/project 偏好，不支持多项目独立开关。操作全局 Skill 会将其限定到本项目；其他项目限定的 Skill 不允许转移。界面明确显示全局、本项目、其他项目。
- 导出读取已保存原文，不导出未保存稿；导入文件、另存位置由原生对话框选择。导入不会覆盖同名 Skill。

## 保存保护

`createDocumentCommands` 在同一原文写队列内重新读取版本，在异步读取之后再次核对 projectId，再调用固定目标写入。原文件以登记元数据 + 完整内容作不透明版本，规格以 revision + 投影内容作版本，Skill 以原位置 + 完整内容作版本。不得拿这些版本串当 UI 文本输出。

同一渲染进程的并发写串行；切项目、只读、版本变化均拒绝。已经开始的写入只使用捕获的原项目路径，迟到回执只更新原稿；保存中继续输入保留新文字。失败不清稿。核对原文后可以显式确认“基于最新版本保留草稿”，不会自动消解冲突。

规格现有命令先改内存再落盘。如果落盘失败，未保存稿仍在；核对原文会看到内存已改后的版本，需显式确认基线后重试。没有回滚其他人的改动。

边界：这不是跨进程/外部编辑器文件 CAS；读后到文件写入之间仍可能有外部竞争。未改 Rust，也未新增跨文件事务。草稿仅跨工作面/项目切换保留，不保证应用退出后恢复。

## 剪辑来源 Props

```tsx
const timelineSource = useWorkspaceTimelineSource(project.id);
{timelineSource && <WorkspaceTimelineSource {...timelineSource} />}
```

组件为 `src/components/workspace/WorkspaceTimelineSource.tsx` default export。主轨传 main、叠加轨传 overlay、音轨传 audio。使用原 `EditorClip/OverlayClip/AudioClip` 的 id/path，主轨可带 sourceNodeId。不要传 proxyPaths、预览 URL 或当前采用路径。

`src/lib/workspace/useWorkspaceTimelineSource.ts` 提供生产hook及 `readWorkspaceTimelineSourceContext(projectId, clipKind, clipId)` 实时只读port。它读取现有workshopStore和已水合editorStore，并核对editorPersist的ready/projectId/activeProjectId。无匹配返回null。无需另读editor.json，无生成/同步/复制；父应在 `await switchEditorProject(projectId)` 完成并更新ready状态后渲染，以覆盖水合状态本身没有订阅事件的现有边界。

hydrated editorProjectId从 `src/lib/editor/editorPersist.ts` 的 `getEditorHydrationState()` 读取，不在editorStore字段中：只有 `status === 'ready' && projectId === 父项目ID && activeProjectId === 父项目ID` 时使用activeProjectId。`getActiveEditorProjectId()` 单独不足以判断已水合，加载过程中可能还是旧ID。镜头身份沿迁移器使用 `shot.id ?? shot.shotNo`，无id旧镜头也可查来源和打开同一Inspector。

解析 `data.projectObjects.media/versions/objects` 和真实 shots：严格实际 path 优先；已有明确 versionId/mediaId 时必须与 path 一致。生成参考关联不视为产物来源。当前 EditorClip 没有这些版本字段，不要虚构或自动写入。遇同路径多归属、同媒体多版本、原镜头删除、跨项目、未归类时显示原因，不猜当前采用版。无历史版本号只显示“版本未记录”。不调用选版、复制、addClips 或 setState，不改时间线。

可传 `onRequestInspector(request)` 让父直接处理；不传时发出 DOM 自定义事件：

```ts
WORKSPACE_INSPECTOR_REQUEST_EVENT = 'kunpeng:workspace-inspector-request'
// CustomEvent<WorkspaceInspectorRequest>.detail
{
  schemaVersion: 1,
  origin: 'timeline',
  projectId, clipKind, clipId, path,
  objectId, mediaId, versionId, outputType,
  intent: 'inspect' | 'edit-prompt'
}
```

接收端必须根据 clipKind/clipId 查**实时 editorStore** 的相应片段，调用 `validateTimelineInspectorRequest(data, activeEditorProjectId, liveClip, event.detail)`。null 就拒绝。通过后仅设置父工作台共享 Inspector 的对象/媒体/编辑态，使用同一 MediaInspector，不能新建项目、镜头或时间线片段。锁定对象会自动降为 inspect。若想保持剪辑工作面，可把同一个 Inspector 作为项目壳覆盖层；不要同时挂两份预览器。

```ts
const context = readWorkspaceTimelineSourceContext(projectId, detail.clipKind, detail.clipId);
const request = context && validateTimelineInspectorRequest(
  context.data, context.editorProjectId, context.clip, detail,
);
if (!request) return;
// 用request.objectId/mediaId/outputType打开父壳现有Inspector；不修改片段path。
```

## Editor 嵌入

```tsx
{surface === 'editor' && <EditorView embedded onSendMessage={send} onAbort={abort} />}
```

`EditorView.embedded` 默认 false，兼容旧调用。true 时不挂 EditorTopBar/EditorChatPanel，仍保留 EditorToolbar、预览、左右专业面板、时间线、剪口播、计划、快捷键和框选。新 `EditorEmbeddedTools` 位于时间线上方，默认折叠，保留模式、画幅、自动字幕、智能剪口播、AI 剪流畅、AI 配特效、原 ExportDialog。全局侧栏开关由父壳负责；快捷键入口原 EditorToolbar 已有。

父应仅在 editor surface 挂载，并在 editor 项目 ready、身份一致后挂载；否则全局快捷键、预渲染和空 store 可能误作用。不要仅 CSS 隐藏整个 EditorView。底层项目水合/落盘仍沿现有 editorPersist，不从此组件复制时间线。

**统一助手接线必须补上**：嵌入态不挂原 EditorChatPanel，其事件监听也随之移除。父壳处理 `kunpeng-editor-prompt` 的 `{prompt}`，捕获当前项目与剪辑范围后送入同一助手队列；处理 `kunpeng-editor-drawer-open` 打开同一助手。旧属性面板、时间线、AI 框选均沿用这些事件。不要额外挂 EditorChatPanel 做隐形转发，否则会重复消费或保留第二条队列。`onSendMessage` 本身不会自动消费该 DOM 事件。

布局建议：保留原左右专业工具；窄宽度下父壳优先收起共享助手/目录，避免同时占四栏。EditorView 的原左右最小宽度仍为 260/240，不能宣称390px专业剪辑面已经响应式验收；本模块390px证据只覆盖文档与来源条。
