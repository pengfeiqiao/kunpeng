# 原有能力保留与新界面整合审计

2026-09-05。本表是当前代码与产品研究的核对结果，不代表所有接入已经完成。

## 产品边界

用户最新要求优先于早期方案中的替代式实现：在鲲鹏现有工坊、专业画布、剪辑模块上增量优化。不恢复故事板拼图；导演约束卡保留。

## 界面细节取舍

1. 工坊保留结构化创作，画布保留自由专业操作，剪辑保留成熟时间线；同一项目中共享对象、版本与任务，而不是用一种卡片取代全部功能。
2. 项目顶栏只表达工作面。剧本与拆解属于工坊内容操作，不重新增加一排全局阶段菜单。
3. 角色音色放角色旁，配音放镜头旁，色卡放项目配色与镜头覆盖处。原功能必须有可发现的手动操作，不能只靠 Agent 猜测工具。
4. 结果优先：素材按原比例查看；版本条紧邻媒体；提示词按当前输出类型展开，生成按钮固定；参考缩略图不替代实际提交原图。
5. 助手默认短阶段摘要、真实产物和实际 Skill 回执，展开看细节；不虚构完成阶段或把底层参数作为主要视觉内容。
6. 调整字号、密度、边框、选中态和留白，不大量套卡片装饰。

## 已发现的接入风险

- 旧 StepScript 异步更新项目来源时缺少完整的当前项目/修订检查，直接挂新入口会扩大串项目风险。
- 旧步骤广播预制 prompt，新助手却使用当前局部对象线程接收；项目级拆分可能被错误绑定到单镜头。新入口需要明确项目级上下文。
- 旧音色/配音直接调用语音客户端，不能在没有确认、重复提交和迟到结果保护的情况下原样扩大入口。这是安全适配，不是删除该功能。
- 新图像优化器中的 MJ 分支目前较简化，未完整利用原专属风格系统；原库仍在，需要接回而非宣布等价。
- “原组件存在”只能证明底层保留，不能证明新界面功能完整。每项还需点击路径和 mock 回归证据。

## 验收纪律

分开记录：原能力仍在 / 新入口可操作 / 数据与任务关联已测 / 真实付费尚未验证。未完成的新入口不能以“兼容模式可找到”作为最终交付。真实付费验证由用户执行，开发过程不提交付费任务、不读取密钥、不改 Rust 或 DSH。

当前离线证据：scriptTools 的项目/来源 CAS 测试；productionSafety 的取消、重复点击、提交歧义、部分成功、切项目、状态日志乱序测试；productionPorts 用 fake ports 调用原 generateShotAudio/trimAudiosToFit；workspace-media-smoke 点击“配音与配色”只改变工具目标、不提交生成。源码组件测试不等于原生 UI 验收，原生编译和实际点击另在实施报告记录。
