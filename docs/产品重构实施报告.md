# 鲲鹏产品重构实施报告

## 1. 实施结论

本轮按照《鲲鹏产品重构最终方案》完成了 P0、P1 的核心产品闭环，并在保持仓库可编译、全量行为测试通过的前提下完成了 P2 的快照与分支、Skill 可见化、一句话建项目、删除语义和执行信息补充。

实现采用渐进收编：以现有 `WorkshopData` 为业务主数据，`canvasStore` 继续负责画布布局和连线，新增统一对象注册表、稳定对象 ID、来源、版本和关系索引。没有推翻现有 store，也没有删除旧项目磁盘数据。

付费生成默认仍为“仅付费生成前确认”。本轮没有弱化 `billingSafety`，没有真实网络调用，没有修改 Rust、DSH 上游、Kimi、GLM 或 DeepSeek Harness 降级逻辑，也没有打包 DMG 或执行 Git 写操作。

## 2. 逐节实施状态

### 一、最终定位：已实现

工坊、画布、剪辑和普通对话共享项目 ID、项目规格、当前对象、媒体版本和对话上下文。主要落点：

- `src/stores/unifiedProjectStore.ts`
- `src/lib/projectObjects/types.ts`
- `src/lib/projectObjects/selectors.ts`
- `src/lib/projectObjects/viewState.ts`

### 二、核心设计原则：已实现

统一对象以稳定 ID 关联，生成结果先成为候选版本，不自动成为参考素材；Agent 写入有版本校验、锁定和撤销；付费操作继续受现有安全闸约束。

### 三、整体信息架构：已实现

现有五个顶层视图未被重写，统一项目层在视图之间同步选中镜头、当前对象和对话。项目顶部新增紧凑规格摘要，详情按需展开。

### 四、删除故事板中间层：已实现，采用兼容下线

更正：旧项目故事板在注册表中迁移为 `historical` 历史素材，文件和旧字段保留。不存在 `excludedFromReferences` 字段。工坊默认参考集合排除故事板；画布参考收集以目标节点的显式参考边/参考列表为准，不能从历史素材标签推断所有旧画布边已经迁移。

落点：`src/lib/projectObjects/migrate.ts`、`src/lib/workshop/shotRefs.ts`、`src/lib/canvas/collectRefs.ts` 及工坊相关步骤页面。

取舍：没有物理删除旧字段或旧文件，避免损坏用户已有项目和恢复链。

### 五、导演约束卡：已实现

导演约束卡收进镜头详情的“空间与调度”，支持场景继承与单镜覆盖，并显示当前继承来源。它仍可作为显式参考参与提示词，但不再成为与视频提示词并列的独立主流程。

### 六、工坊与画布双向联动：已实现

工坊新对象进入画布待整理区，不重排用户布局；“在画布中查看”只定位和高亮。画布空白生成进入未归类素材；视图切换保留镜头选择和对话。

落点：`src/lib/workshop/canvasSync.ts`、`src/lib/workshop/canvasSyncModel.ts`、`src/stores/unifiedProjectStore.ts`、`src/stores/canvasStore.ts`。

### 七、统一项目对象：已实现

建立方案要求的统一对象类型、稳定 ID、来源、版本、关联关系和当前版本索引。Workshop 继续保存业务内容，Canvas 只保存空间布局和边关系，通过对象 ID 关联，减少副本漂移。

### 八、媒体用途和版本体系：已实现

更正：生成结果默认候选版本或未归类素材。无目标的注册表参考开关已退出；参考必须通过目标节点的显式参考边/参考列表指定，媒体用途、归属和采用状态都不创建参考。旧 `generation-reference` 用途兼容读入为普通素材。切换版本保留历史和连线，锁定版替换有独立保护；旧节点的当前图路径仍是兼容参考边的取图来源，历史任务参数快照需在新工作台阶段继续完成。

落点：`src/lib/projectObjects/types.ts`、`src/lib/projectObjects/selectors.ts`、`src/lib/canvas/collectRefs.ts`。

### 九、项目规格卡：已实现

项目顶部提供紧凑摘要和展开编辑；规格注入普通对话、工坊、画布、剪辑 Agent 上下文。规格中的生成确认默认值固定为 `paid-only-confirm`。

落点：`src/lib/projectObjects/projectSpec.ts`、`src/components/projects/ProjectTopBar.tsx`、`src/hooks/useAgent.ts`。

### 十、可隐藏的 Agent 抽屉：已实现

抽屉支持展开、收起、隐藏，状态按项目记忆；隐藏或收起时，新回复以轻量状态提示呈现，不强制撑开界面。既有对话继续沿用同一项目会话。

落点：`src/components/chat/AgentDrawer.tsx`、`src/lib/projectObjects/viewState.ts`。

### 十一、统一“添加到对话”：已实现

支持菜单添加、拖入抽屉、当前对象条、多对象引用和保留 `@` 语义。引用气泡携带类型、所属项目、版本及操作范围，Agent 接收的是稳定对象引用而非临时 UI 文本。

落点：`src/lib/projectObjects/conversationRefs.ts` 及画布、工坊、对话输入组件。

### 十二、AI 修改与人工修改：已实现

Agent 修改前校验对象版本；用户刚修改过或已锁定的对象不会被静默覆盖。冲突进入跳过、保留人工版本或重新应用的处理路径。修改结果生成字段级摘要，并支持撤销本轮修改。

落点：`src/lib/projectObjects/collaboration.ts`、`src/lib/projectObjects/workshopCollaboration.ts`、`src/stores/unifiedProjectStore.ts`。

### 十三、生成草稿与付费信任：已实现

生成前草稿包含完整提示词、按顺序排列的引用、模型参数、数量、费用预估和可能的降级说明。三档偏好均已支持，默认仍是仅付费生成前确认；取消草稿不会调用供应商。

落点：`src/lib/projectObjects/generationDraft.ts`、`src/lib/canvasGen/index.ts` 及生成面板。

### 十四、模型与参数：已实现

切换模型时根据 catalog 能力表校准时长、比例和参考素材数量，非法值被夹紧并向用户展示具体调整项。不可用模型保留可见但置灰，并提供配置或修复入口。

### 十五、镜头界面：已实现

镜头默认显示六项核心信息，详情按需展开，并保留紧凑列表和视觉卡片两种密度。导演约束卡并入详情，减少顶层并列入口。

### 十六、回退、快照与分支：已实现

每条成功修改消息可记录项目数据快照，支持“回到此刻”和“创建分支”。回退只恢复结构化项目数据，不删除、回滚或伪造媒体文件；分支共享媒体引用。存在生成中任务时会警告，已提交供应商任务不会被标成撤销。

落点：`src/lib/projectObjects/snapshots.ts`、`src/components/MessageList.tsx`、`src/stores/projectStore.ts`、`src/stores/unifiedProjectStore.ts`。

取舍：本轮提供可靠的恢复和分支入口，未增加复杂的逐字段快照差异浏览器。

### 十七、Skill 可见化：已实现

技能库显示来源、启用状态、全局或项目范围和最近使用时间，支持启停、项目限定、打开编辑、Markdown 导入导出；执行链标注实际使用的 Skill。

落点：`src/lib/skills/skillPreferences.ts`、`src/components/skills/SkillLibrary.tsx`、`src/lib/agent/skillLoader.ts`、`src/lib/agent/skillPromptPolicy.ts`、`src/lib/agent/tools/skillInvokeTool.ts`。

取舍：编辑动作打开技能源文件，未另造一套内嵌 Markdown 编辑器，避免与现有技能加载和同步机制产生双写。

### 十八、新手入口与自动化：已实现核心入口

项目页提供一句话建项目，识别想法、剧本、素材和参考片，并支持逐阶段确认或连续执行偏好。输入结果写入项目规格和 Agent 交接上下文。

落点：`src/lib/projects/projectIntake.ts`、`src/components/projects/ProjectListView.tsx`。

取舍：附件在入口阶段记录为待导入项，由后续 Agent/用户确认用途后正式建对象，避免未经确认把所有附件自动设为生成参考。

### 十九、执行过程表达：部分实现

统一对象操作、Skill 调用、生成确认和恢复动作已有可读阶段状态；原有执行链继续承担工具细节的按需展开。

未做：没有在本轮重写所有遗留工具的进度文案。原因是这会跨越大量既有模型与工具行为，风险高于当前项目一致性目标。

### 二十、视觉与交互语言：部分实现

本轮新增的规格条、抽屉三态、引用气泡、草稿卡、删除提示、快照入口和 Skill 页面采用一致的图标、间距和层级。快捷键沿用现有约定。

未做：没有全量翻修所有历史页面的视觉样式和快捷键体系，避免把大范围纯 UI 改动混入数据模型重构。

### 二十一、删除语义：已实现

明确区分“从当前视图移除”和“从项目删除”。前者只删除布局节点，保留项目素材；后者先计算版本、连线、镜头和提示词影响范围，确认后删除，并提供撤销提示。

落点：`src/lib/projectObjects/deletion.ts`、`src/components/canvas/ProjectDeleteUndoToast.tsx` 及画布菜单。

### 二十二、最终主流程：已实现主链

从一句话建项目、规格确认、工坊拆解、素材生成、画布整理、Agent 修改审阅到剪辑交付，共享同一对象和版本体系。已有专业手工路径继续保留。

### 二十三、优先级建议：已按序执行

P0 和 P1 完成并通过全量测试后才进入 P2。P2 完成快照/分支、Skill 可见化、新手入口、删除语义和执行信息接入；全局视觉深改保守留待后续。

### 二十四、明确不做：已遵守

没有把工坊强制改成画布，没有把所有操作自动化，没有自动把产物设为参考，没有把 Agent 抽屉设为永久展开，没有用物理删除替代兼容迁移。

### 二十六、一句话总结：已实现

鲲鹏现在以同一项目对象和稳定版本关系连接工坊、画布、剪辑与 Agent，用户可以在自动化与手动控制之间切换，而不会让产物、参考和修改权限悄悄混在一起。

## 4. 数据迁移与兼容策略

- 迁移在读取和统一对象投影阶段幂等执行，不直接重写或删除 `~/.kunpeng/` 下旧文件。
- 旧故事板转换为历史媒体对象并标记排除参考，不占用 `@图片N`。
- 缺少统一对象字段的旧项目按稳定来源键补齐 ID；重复读取不会重复创建对象。
- 旧 Canvas 布局、连线和任务恢复 ID 保留；统一对象层只增加引用，不改变任务所有权认领。
- 新字段均为向后兼容的可选结构，旧版本仍可读取其认识的主体数据。

## 7. 取舍与遗留风险

1. 统一对象采用渐进投影，没有一次性删除 Workshop/Canvas 旧字段。这样会在过渡期保留少量双结构，但显著降低旧项目损坏和恢复链回归风险。
2. 旧故事板被兼容下线而非物理删除。历史项目仍能查看原图，但它们默认不参与新生成。
3. 拉片复刻复用了“一句话项目入口 + 参考片识别 + 现有 Agent/时间轴工具”，未新增另一套重型向导，以免形成新的中间层。
4. 快照目前强调恢复和分支，未提供完整逐字段 diff 浏览器；结构化数据回退和媒体引用安全已覆盖。
5. Skill 编辑复用外部文件编辑，避免内嵌编辑器与磁盘 loader 双写。
6. 全应用历史视觉与所有工具进度文案没有在本轮彻底重写。新增界面已统一，但遗留页面仍可继续做单独的视觉治理。
7. 主 bundle 仍较大，构建会给出分包提示。这是既有架构性能债，不影响本轮功能正确性，后续可独立做 lazy loading 和 manualChunks，避免与项目模型重构耦合。
