# 助手对话设计精修

## 调研观察

以下调研观察仅记录界面行为，不涉及内部实现：

- 右栏标题为“对话”，助手正文不逐条显示头像或作者行。
- 用户请求较窄、右对齐；助手用简短自然段穿插执行阶段。
- Resource Preparation / Media Assets 等阶段可折叠，收起时仍有实际媒体缩略图；展开后显示纵向步骤、成功状态和必要记录。
- 输入框位于底部。

借鉴的是阅读顺序与信息密度，不复制品牌、阶段名称或未经本产品数据支持的完成声明。

## 本次取舍

1. 回复顺序为完整正文、真实运行记录、产物与变更摘要。删除逐条 Sparkles 与“鲲鹏”作者行，embedded 抽屉不再挂隐藏的重复标题 DOM；父布局负责“对话”标题。
2. 长回复只渲染一次完整 Markdown，不以字符数截断，不拆开代码块或复制完整回复。内容长短由真实回复决定，呈现层不改写文字。
3. 执行记录默认折叠。记录来自消息绑定的 `runId`，展开后按真实 run 事件排列竖向步骤；没有记录时不生成假的资源准备阶段。
4. 总状态以 run 终态优先，再检查真实步骤、工具和子任务记录。已结束但仍有 pending/running 记录显示“未完成”，不悬挂在等待中；仍在重试的运行显示“执行中 · 有失败记录”。停止、跳过不会被显示为成功。
5. 缩略图只来自成功、结构化工具回执与当前项目媒体 registry 的交集。缩略图属于整次回复，不凭名称猜测它属于哪个步骤。音频以音频标识呈现，不伪造波形或时长；实际打开仍进入共享 Inspector。
6. 产物明细默认折叠，保留原版本与候选信息。消息菜单里的快照恢复、字段改动、撤销、提示词回执和执行记录入口保留。
7. 移除独立 Skill 标签行。只有真实 `skill_invoke` 工具记录且存在具体 `display.detail` 时，才提供可展开的技能详情；查看技能目录不等于使用某项技能。
8. embedded 正文为 13px，阶段为 12px，辅助信息为 11px；按钮和输入区保持紧凑，工具行可换行。输入区仍是原 flex 布局的非滚动尾部，没有改为覆盖消息的悬浮层。
9. 旧非 embedded 分支保持原标题、问候、气泡、步骤组件及输入控件；模型选择、Skill 执行、确认、发送、队列、权限、付费和 runtime 没有改动。
